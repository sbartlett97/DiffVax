## What we learned (all FLUX.2 Klein 4B edit mode, 512px, validation images)

| Approach | Edit vs clean, excess over noise | Identity of edit vs original | Visibility | Verdict |
|---|---|---|---|---|
| v1 generator through the full editor (9 epochs) | +0.19 | edits kept the person | SSIM 0.77, stripe texture | not useful |
| v2 generator + LPIPS/CLIP losses | +0.016 | n/a | invisible (SSIM 0.997) | collapsed to ~0 |
| Generator on encoder objective (tanh bound) | none | none | invisible | saturated tanh: no gradient (bug, fixed: `bound="ste"` + small init) |
| Per-image PGD, encoder -> gray latent, eps16, JPEG EoT | +0.31 (holds after JPEG) | person changes in edits | SSIM 0.59 | strong but visible |
| Per-image PGD, encoder, eps16 + LPIPS<=0.05, 20 imgs, after JPEG | +0.25 | **0.13 vs 0.49 clean / 0.39 noise -> IDENTITY PROTECTED** | LPIPS 0.05 but SSIM 0.62: visible 8px mesh at 2x zoom | protects, still visible |
| Sweep (running at wrap-up): eps8+SSIM>=0.95, eps8+SSIM>=0.97, eps4 | see `outputs/pod_2026-11-11/outputs/protocol_sweep_*/protocol_report.md` | | | **decides the teacher setting** |

Key conclusions:
1. The VAE-encoder attack (push the editor's latent of the photo toward a flat-gray
   latent) makes Klein edits depict a different person, and survives JPEG when optimised
   through JPEG/resize EoT. This is the most promising mechanism found.
2. LPIPS alone is not a usable "imperceptible" bound; use SSIM (and eyeball 2x crops).
3. The one-shot generator does not yet learn it on its own (normalised encoder loss
   0.93 vs PGD's ~0.25-0.40). Next: distil from PGD teachers.

## Restarting a pod

```bash
runpodctl user                                   # balance (was ~$8.8 at wrap-up)
runpodctl pod create --name diffvax-a100 --image runpod/pytorch:1.0.3-cu1281-torch291-ubuntu2404 \
  --gpu-id "NVIDIA A100-SXM4-80GB" --cloud-type SECURE --data-center-ids US-MD-1 \
  --volume-in-gb 150 --volume-mount-path /workspace --container-disk-in-gb 50 \
  --ports 22/tcp --env '{"HF_TOKEN":"{{ RUNPOD_SECRET_HF_TOKEN }}"}'
runpodctl pod get <id>                           # ssh ip/port under "ssh"
rsync -az --no-owner --no-group -e "ssh -i ~/.ssh/id_ed25519_runpod_2 -p <port>" \
  --exclude .venv --exclude .git --exclude outputs --exclude data ./ root@<ip>:/workspace/DiffVax/
# on the pod (HF_TOKEN must be exported from /proc/1/environ in ssh sessions):
export HF_TOKEN=$(tr "\0" "\n" </proc/1/environ | sed -n "s/^HF_TOKEN=//p")
bash scripts/runpod_setup.sh                     # uv venv, torch pinned to the template build
python scripts/rewrite_edit_prompts.py --data-dir data --write   # instruction-style edit prompts
```

Gotchas seen today: A100 SXM stock is scarce (poll); US-MD-1 has no network volumes;
publish `22/tcp` at creation; `pgrep/pkill -f` patterns must be anchored (`^python ...`)
or they match the ssh command itself; the Discord webhook goes in `/root/.discord_env`
(the `/workspace` filesystem ignores chmod).
