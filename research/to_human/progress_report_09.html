What Just Happened (Important)

H1a Training Bug Diagnosed: max_steps Was Never Enforced

Root cause: DiffVaxImmunization.__init__ extracted individual config values but never stored self.config = config. The line max_steps = self.config.get("max_steps", None) would raise AttributeError — meaning the GPU ran old code without max_steps at all, continuing past 8,000 steps for all 10,000 epochs.

Result: Training ran 26+ epochs (≈41,600 steps) and converged — but no checkpoint was saved (only saves at epoch 10,000 or on NaN loss).

Action required: kill training, git pull, restart.
All Three Bugs Fixed and Committed
  1. self.config = config added to DiffVaxImmunization.__init__ — max_steps now works
  2. Periodic checkpoints every 5 epochs (checkpoint_every: 5, configurable)
  3. Stop-file mechanism: touch /tmp/diffvax_stop → saves checkpoint and exits cleanly
git pull
python scripts/train.py --config configs/train_multimodel.yml
With fixes: stops after 8,000 steps (~5 epochs ≈ 3.3h at 1.5s/step). Saves checkpoint at epoch 5 AND final.pth.

Good News: Model Has Converged

Despite the bug, 26 epochs of training produced a fully converged model. The loss data is actually valuable — it documents convergence speed for the paper.
