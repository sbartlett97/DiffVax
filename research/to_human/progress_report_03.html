1. H2 CPU Preliminary — Patch Overlap Analysis

Ran a seam-artifact analysis at 1088×1088 to determine the minimum overlap needed for coherent patch tiling. The NestedUNet is truly resolution-agnostic, but Gaussian blending requires sufficient overlap to avoid boundary artifacts.

StrategyStrideOverlapSeam RatioResult
No overlap5120% 2.377 FAIL
25% overlap38425% 1.275 Marginal
50% overlap25650% 1.046 PASS

Decision: stride=256 (50% overlap) is now the default for patch_immunize(). This doubles compute vs no-overlap but is required for artifact-free results. The seam ratio threshold used is 1.2 (artifact ≤20% above baseline).

Key Research Context

Why This Matters — The Purification Threat

The paper "Purify Once, Edit Freely" (arXiv:2603.13028) shows that all current immunization methods (Glaze, PhotoGuard, DiffVax-SD15) can be defeated by running FLUX.1-fill-dev as a purifier before editing:

  • Purification recovers +3–6 dB PSNR and reduces FID by 50–70%
  • This is a practical product threat, not a theoretical attack
  • Our H1a/H6 experiments test whether training DiffVax against FLUX can defeat this

Core Hypothesis Summary

HypothesisMechanismExpected Outcome
H1a Multi-model training (SD+FLUX) transfers to unseen architectures EDR on FLUX.1-schnell ≥ 0.8 (vs ≤ 0.3 for SD-only trained)
H2 Patch-based inference at 1088px without retraining EDR ≥ 80% of native 512px performance
H6 FLUX-trained immunization resists FLUX-based purification SSIM delta after purification < 0.05 for DiffVax-FLUX (vs > 0.2 for DiffVax-SD15)
H4 VAE feature loss improves cross-architecture transfer +15% EDR on SD3.5 compared to H1a without VAE loss
