Critical Bug Found and Fixed: Attention Block Targeting

Bug (Production Config)

Phase 7 in full_v2.yml was configured with attention_loss.target_blocks: "early". DeContext (arXiv:2512.16625) shows that middle transformer blocks carry the primary context-propagation signal in MM-DiT models, not early blocks. Training with early-block hooks was providing essentially no disruption signal to SD3.5 and FLUX. Fixed to "middle" in all v3 configs and corrected in full_v2.yml.

Implementation Details

H5: SpectralLoss (New Module)

Penalises low-frequency energy in the perturbation δ = img_adv − img_orig using torch.fft.rfft2. Concentrates perturbation energy in high-frequency bands (less perceptible to humans, still disruptive to VAEs).

SpectralLoss( low_freq_radius=0.1, # central 10% penalised weight=0.5 # via LossComposer ) → rfft2(δ, norm="ortho") → penalise |FFT(δ)| where freq < 0.1 → scalar loss added to training objective
Prediction
SSIM +0.02–0.05 and PSNR +1–3 dB at same epsilon budget. Orthogonal to H1/H2/H4/H7 — can be stacked.

H6: Configurable NestedUNet

Added nb_filter parameter to NestedUNet.__init__. PyTorchModelHubMixin serialises it to config.json for Hub checkpoint compatibility.

# Default (unchanged behaviour): NestedUNet(num_classes=3) # → nb_filter=[32,64,128,256,512] # → ~9M parameters # H6 larger variant (opt-in): NestedUNet(num_classes=3, nb_filter=[64,128,256,512,1024]) # → ~37M parameters # → incompatible with existing ckpts
Surprise
Actual param count is 9M (small), 37M (large) — not 1.8M/7M as estimated. UNet++ dense skip connections inflate count vs plain U-Net.

Architecture of v3 Training Bundle

Loss = loss1 + loss2 + loss_clip + loss_attn * attn_weight + loss_spectral loss1: L1( attack_output − target ) # H7: target = ±1 noise (was: zeros) loss2: L1( alpha * delta ) # perturbation magnitude penalty loss_clip: CLIP-H/14 feature distance # H3: DALL-E 3 coverage via ViT-H-14 loss_attn: entropy of middle DiT blocks # H1: middle blocks (was: early) loss_spectral: rfft2 low-freq magnitude # H5: push perturb into high-freq bands Backward: SD3.5/FLUX: backprop only first 50% timesteps # H2: 50% VRAM reduction SD3.5/FLUX: TGR backward hooks on DiT blocks # H4: stabilise token gradients
